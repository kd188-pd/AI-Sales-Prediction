# AI-Based Sales Prediction and Business Analytics System

A beginner-friendly Python + Flask web application that trains a Random Forest regression model to estimate product demand, calculates estimated sales revenue, displays analytics from user-saved predictions, stores results in SQLite, and exports CSV files.

> **Academic demo disclaimer:** The included dataset is synthetic demonstration data generated by `generate_data.py`. It is not real company sales. Model metrics only describe the model's performance on a holdout subset of that synthetic dataset; they must not be presented as proven real-world accuracy.

## Dashboard data policy

The dashboard starts empty and displays **only predictions submitted by the user and saved to the local SQLite prediction history**. KPI cards, category summaries, monthly forecast revenue, and recent-prediction charts do not read from the synthetic training CSV or offline model-evaluation output. The synthetic dataset is used only to train and evaluate the ML model; it is not presented as the user's business history.

## Features

- Dashboard KPIs derived only from user-saved predictions: estimated revenue, prediction count, average estimate, predicted units and categories tested.
- Monthly saved-forecast revenue and product-category charts based only on prediction history.
- Recent saved forecasts chart; the dashboard starts empty until the user generates a prediction.
- Sales prediction form using category, price, discount, marketing spend and the selected date.
- Random Forest regression pipeline with one-hot categorical encoding and standardized numeric features.
- Model evaluation with MAE, RMSE and R².
- SQLite prediction history that persists after the app is restarted.
- CSV download for the synthetic dataset and saved prediction history.
- Responsive light dashboard with desktop sidebar and mobile navigation.

## Run on Windows

Open Command Prompt in this project folder. If you have extracted the ZIP, open the `AI_Sales_Prediction` folder first.

### Option A: Automated setup

Double-click `run_project.bat`. It creates a virtual environment if needed, installs packages, generates sample data, trains the model, then starts Flask. Leave that terminal open while using the website.

### Option B: Run manually

```bat
py -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python generate_data.py
python train_model.py
python app.py
```

Then open **http://127.0.0.1:5000** in Chrome or another browser.

If `py` is not recognized, try `python` in its place. When the application is running, press `Ctrl+C` in the terminal to stop it.

## How the model works

1. `generate_data.py` creates 2,000 reproducible synthetic sample rows across five product categories and date ranges.
2. `train_model.py` checks the dataset and sorts it by date.
3. The earliest 80% of records are used for training and the latest 20% for holdout evaluation.
4. A scikit-learn pipeline applies `OneHotEncoder(handle_unknown="ignore")` to product category and standardizes numeric features.
5. `RandomForestRegressor` predicts `units_sold` from product category, unit price, discount, marketing spend, weekday and month.
6. The trained pipeline is saved to `models/sales_model.joblib`. Metrics and holdout predictions are saved separately.
7. Flask loads the trained pipeline once at startup and uses the same preprocessing at inference time.
8. Estimated sales revenue is calculated as:

   `Predicted units × Unit price × (1 − Discount percentage / 100)`

Predicted unit counts are rounded to a non-negative integer for the user interface. The resulting revenue is an estimate, not a guarantee.

## Test the application

With dependencies installed, run:

```bat
python -m unittest discover -s tests -v
```

The tests exercise the Flask routes, prediction save flow, input validation, and CSV downloads.

## Limitations and future enhancements

- Data is synthetic; production usage needs validated, representative business history.
- The training procedure uses a chronological holdout split but does not claim production readiness.
- The current model predicts unit demand; revenue is calculated from that estimate and the discount.
- Future work could include real point-of-sale integrations, promotion calendars, confidence intervals, forecasting by store/SKU, model monitoring and role-based accounts.
